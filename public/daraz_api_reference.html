Sonic — Daraz Booking API

Technical reference for integrating Daraz shipment booking with the Sonic logistics platform.
Version 2.0 May 2026 Confidential — Daraz × Sonic
1 Quick Start
Base URL: All API calls are made to the Sonic production endpoint. Daraz must send requests from whitelisted Daraz account IDs only — any other account will receive a "Shipper is not allowed" error.

Endpoint

POST https://<sonic-domain>/api/shipment/book/daraz

Required Headers

HeaderValue / FormatNotes
Authorization {api_token} Raw token — no "Bearer" prefix. Issued per Daraz account by Sonic ops.
Content-Type application/json Request body must be JSON.
Via daraz-integration (recommended) Optional. Logged for source identification.

Response Format

All responses return HTTP 200 with a JSON body. Use the status field to determine success:

statusMeaning
0Success — shipment booked
1Error — see message and optional errors fields
2 Request Parameters

Tracking Number

FieldTypeRequiredRules
tracking_number integer Required Must be unique across all shipments. Must begin with a prefix assigned to the Daraz account by Sonic. Example: if prefix is TRX, then TRX00012345.

Pickup Address

FieldTypeRequiredRules
pickup_address_id integer Required ID of a pre-registered pickup address belonging to the authenticated Daraz account. Must not be hidden or disabled. City must be active and pickup-enabled.

Return Address

If no existing return address matches the (vendor, city_id, phone) combination, Sonic auto-creates one. Supply all 6 fields on every request.

FieldTypeRequiredRules
return_addressstringRequired1–255 characters. Full street address.
return_contact_personstringRequired1–100 characters.
return_vendorstringRequired1–100 characters. Used as the address label / vendor name.
return_phone_numberstringRequiredValid Pakistan phone number. See phone format table below.
return_email_addressstringRequiredValid email, max 100 characters.
return_city_idintegerRequiredMust be an active city ID in Sonic's city table (business_category = 1).

Consignee

FieldTypeRequiredRules
consignee_namestringRequired1–100 characters.
consignee_addressstringRequired1–255 characters. Full delivery address.
consignee_city_idintegerRequiredActive city ID with delivery enabled. Must be reachable under the selected shipping mode.
consignee_phone_number_1stringRequiredValid Pakistan phone. See phone format table.
consignee_phone_number_2stringOptionalValid Pakistan phone. Ignored if blank.
consignee_email_addressstringOptionalValid email. Ignored if blank.

Shipment Details

FieldTypeRequiredRules
shipping_mode_id integer Required 1 = Rush  |  2 = Saver. Mode must be active on the Daraz account's rate card. Modes 3 and 4 are not available for Daraz.
estimated_weight numeric Required Weight in kg. Range: 0.1 – 100,000.
amount numeric Required Cash on Delivery amount in PKR. Use 0 for prepaid. Range: 0 – 1,000,000. Must not exceed the COD cap for the destination zone class. If 0, a parcel_value must be provided.
item_description string Required Up to 500 characters. Description of shipment contents.
item_quantity integer Required Number of items. Range: 1 – 10,000.
parcel_value numeric Required if amount = 0 Declared value of the parcel in PKR. Range: 0 – 1,000,000. Required for prepaid shipments.

Warning Flags in Success Response

Even with status: 0, the response may include additional warning keys. These do not block delivery but should be reviewed:

KeyMeaningAction
non_service_area A keyword in the consignee address matches a known non-service or out-of-service-area location. Additional charges may apply. Shipment may be returned if area is fully non-serviceable.
blacklisted_consignee The consignee phone number is on Sonic's blacklist. Review the blacklist message. Shipment is still booked; take care with delivery.

4 Tracking Number Rules
Key difference from standard Sonic booking: Daraz supplies its own tracking number in the request. Sonic stores it directly on the shipment after booking. The tracking number must be globally unique and must begin with a prefix pre-assigned to your Daraz account.
1
Sonic ops assigns one or more tracking number prefixes to your Daraz account (e.g. TRX, DRZ).
2
Daraz generates a tracking number using that prefix: e.g. TRX00012345. Must be an integer (no non-numeric suffix characters).
3
Send tracking_number in the booking request. Sonic validates uniqueness and prefix match.
4
On success, Sonic returns tracking_number in the response — same value you sent. Use this for label printing and tracking lookups.
If a prefix mismatch occurs: you will receive "Prefix not matched with given tracking number". Contact Sonic ops to verify the prefix list assigned to your account.
5 Return Address — Auto-Creation Logic

You do not need to pre-register return addresses. Sonic looks up an existing address using the combination (vendor name + city + phone number). If not found, it creates a new one automatically.

1
Sonic looks up user_shipping_infos for a row where vendor = return_vendor, city_id = return_city_id, and phone = return_phone_number.
2
Match found: existing address ID is reused — no new record created.
3
No match: Sonic creates a new address record using all 6 return fields and returns the new ID.
4
The resolved return address must be in a city where return delivery is active for the selected shipping mode.
Best practice: Send the same return_vendor, return_city_id, and return_phone_number consistently for the same warehouse. This avoids creating duplicate return address records over time.
6 Common Validation Errors & Fixes
Error MessageCauseFix
Shipper is not allowed. The authenticated user's ID is not on the Daraz whitelist. Ensure you are using the correct API token for your Daraz account. Contact Sonic ops if a new account needs to be whitelisted.
Prefix not matched with given tracking number The tracking number does not start with a prefix assigned to your account. Confirm prefix list with Sonic ops and regenerate the tracking number.
The tracking number has already been taken. Duplicate tracking number — already exists in Sonic's system. Use a new unique tracking number. Never reuse a tracking number.
Delivery is not available for this City. The destination city has booking disabled by Sonic ops. Check city availability or contact Sonic ops. Retry when city is re-enabled.
Delivery is not allowed for City ID # with Service Type… The selected shipping mode is not active for that city. Switch to a different shipping mode (1 or 2) or choose a different destination city.
Amount must be smaller than or equal to {N} COD amount exceeds the cap for the destination zone class. Reduce the amount or split the order across multiple shipments.
Return city not allowed… The return address city is not active for returns under the selected shipping mode. Use a return address in a return-enabled city. Contact Sonic ops if needed.
Pickup Address ID # is disabled The pickup address has been deactivated. Use a different active pickup address ID. Contact Sonic ops.
Your payable amount balance has exceeded the negative limit. Account has an outstanding negative payable and cannot book zero-COD shipments. Settle outstanding payables with Sonic finance, or use a non-zero COD amount.
The consignee_phone_number_1 field is invalid. Phone number format not recognized. Use a valid Pakistan mobile format: 03XXXXXXXXX (11 digits) or +92XXXXXXXXXX.
7 Booking Flow — What Happens After a Successful Call
1
Authentication validated via Authorization header token. User ID injected automatically.
2
Account whitelist checked — only approved Daraz account IDs can proceed.
3
All request fields validated against the rules in Section 2.
4
Tracking number prefix verified against all prefixes registered to the account.
5
Return address resolved or auto-created.
6
Return city / destination city / pickup city all validated for active status and zone coverage.
7
COD cap checked for destination zone class (inter-city shipments only).
8
Delivery mode availability checked for destination city.
9
Negative payable guard checked for zero-COD bookings.
10
Shipment record created in Sonic's system via the corporate booking engine.
11
Daraz-supplied tracking number overrides the auto-generated one and is saved to the shipment.
12
Booking API log recorded for audit trail.
13
Payment mode log recorded.
14
Consignee and shipper areas resolved and stored on the shipment (used for hub routing and reporting).
15
Consignee address scanned for non-service-area keywords — warning added to response if found.
16
Consignee phone checked against blacklist — warning added to response if flagged.
17
Order date, shipper reference numbers, and item details recorded.
18
Success response returned with tracking_number. The shipment is now visible in Sonic's portal and eligible for pickup scheduling.
