System Overview
What is Finga and how does Trax integrate with it
⌄
ℹ
Finga (also known as Finova or Finja) is a third-party digital wallet provider. Trax integrates with Finga to allow shippers to receive COD (Cash on Delivery) payments directly into their Finga wallet instead of traditional bank transfers.

Key Concepts

📋 COD Flow

When a shipment is created with COD, Trax logs the expected amount to Finga. As the shipment progresses through delivery statuses, Finga is notified. Upon delivery, the COD amount is settled into the shipper's wallet minus applicable charges.

🔄 Queue-Driven

All Finga API calls are dispatched as Laravel queue jobs to ensure reliability. Failed jobs are retried automatically. Bulk operations use dedicated bulk queues for efficiency.

Authentication
Bearer token management and auto-refresh
⌄
⚠
The token is cached in Laravel cache under key wallet_api_token for 3 minutes. All API calls check the cache first and only re-authenticate when the token is expired or missing.
POST

Login / Token Refresh

{FINGA_URL}login/

Authenticates with Finga using the Sonic service account credentials and returns a Bearer token.

Request Body

JSON 
{
  "username": "sonic",
  "password": "***"
}

Response

JSON 
{
  "token": "Bearer_token_here"
}
✓
Token is stored via Cache::put('wallet_api_token', $token, 180) and retrieved with Cache::get('wallet_api_token') before each API call.

👤 Phase 1: Admin Setup

1

Admin adds shipper to wallet settings

Admin navigates to the wallet management panel and adds the shipper's user_id to wallet_shipper_settings with status=1.

2

Shipper sees wallet signup option

Once enabled, the shipper's dashboard shows the Finga wallet signup form. Without this setting, the option is hidden.

💳 Phase 2: Wallet Signup

1

Shipper submits signup form

Shipper provides: name, email, phone, CNIC, and CNIC front/back images.

2

Validation & API call

ShipperDashboardController::updateprofilewalletbulk() validates data, then calls FingaIntegrationController::signUp() which POSTs to wallet/onboard-users/.

3

Store wallet_id & set default bank

On success, creates wallet_users record with the returned wallet_id. Sets Finga bank as default: bank_id=48, IBAN: PK06TMFB0000000087042403.

4

Dispatch pending records job

Dispatches WalletSignUpLPendingRecordLogs job to queue wallet_signup_pending_record_log to backfill existing shipments.

🔄 Phase 3: Post-Signup Pending Records

ℹ
The WalletSignUpLPendingRecordLogs job handles backfilling all existing pending payments for the newly registered shipper.
1

Find all pending payments

Queries all existing pending payment shipments for the shipper that haven't been logged to Finga yet.

2

Send COD log for each shipment

For each pending shipment, sends COD log to Finga via transactions/log/. Updates wallet_log_updated=true in settlement records.

3

Send current status

After COD log is sent, sends the current shipment status to Finga via shipments/update/.

4

Chunked processing

Processes in chunks of 50 shipments with a 20-second sleep between chunks to avoid rate limiting.

📌 Phase 4: Ongoing Status Sharing

1

Status change triggers job

Every shipment status change dispatches ShipmentStatusSharingWithWallet job to queue shipment_status_sharing_with_wallet.

2

Check COD log sent

Job checks finja_log_settlement_records.wallet_log_updated. If false, sends COD log first before proceeding.

3

Check COD amount change

If COD amount has changed since last log, dispatches CODAmountChangeSendToWallet job to notify Finga of the new amount.

4

Send status update

Sends status update to shipments/update/. Updates status_sharing_with_wallets.is_send=1.

5

Cron catch-up

Cron bulk:status-sharing-wallet runs every 5 minutes to pick up any missed statuses (where is_send=0).

💸 Phase 5: Payment Settlement

⚠
Settlement runs daily (except Sunday) via cron wallet-users:make-to-done at 06:00. Admin can also trigger manually via mark_settlement().
1

Move pending to done payments

Cron moves pending wallet payments to done payments for all active wallet users.

2

WalletBulkSettlementFromDonePayments job

Processes each done payment shipment based on wallet_action_bid value:

wallet_action_bidActionAPI EndpointSettlement Record Updated
0Send arrival charge logtransactions/log/chargewallet_log_charges_updated
1Send settlementtransactions/log/settlementwallet_settlement_updated
2Send adjustmenttransactions/log/adjustmentwallet_adjustment_updated
3Already processed—No action needed
3

Update settlement records

After each successful API call, updates the corresponding boolean flag in finja_log_settlement_records.

4

Update payment status

Updates the shipment's payment_status_id to reflect the completed settlement.

🚫 Phase 6: Wallet User Disable

1

Cron runs twice daily

Cron disable_wallet_users runs at 13:00 and 18:00 to check for users that should be disabled.

2

Check for pending payments

Only disables a wallet user if they have no pending wallet payments. Users with outstanding payments are skipped.

3

Archive to wallet_users_disables

Moves the record from wallet_users to wallet_users_disables for audit trail purposes.
